## 3. ФИЛОСОФИЯ ПРОЕКТА (Что мы строим)
NetCity — это не приложение. Это **Убежище для свободного разума**.
- **KVP Protocol:** Наша крепость, защита от корпораций.
- **Digital Self:** Главный ассистент, управляющий триллионами параметров.
- **Spatial Engine:** Пространственный интерфейс, где нет кнопок, только намерения и ассоциации.
- **Дрейф:** Возможность выйти из матрицы, вернуться в прошлое (к бабушкиным пирожкам) или прыгнуть в черную дыру.

## 4. ТЕКУЩИЙ СТАТУС (Где мы находимся)
- **Общая архитектура:** KVP, Digital Self, Architect Runtime и Spatial Engine остаются основой проекта. Нельзя смешивать целевую архитектуру с уже подключёнными компонентами.
- **Технологический стек:** Rust (ядро KVP), React + Three.js (Spatial HUD), локальный ИИ-агент MiMo (AndCode).
- **Визуал:** Концепция Nested Spheres включает купол, семь сфер-реальностей и морфинг в полусферы при входе. Актуальность опубликованного деплоя проверяется отдельно.
- **Spatial Interpreter:** контракты v0.1 и неисполняющий bridge в ArchitectRuntime добавлены.
- **Planner Stage B:** в отдельной ветке `work/spatial-planner` реализован `DeterministicSpatialPlanner` (коммиты `f5aa2ed` и `e75e84f`). Он строит предложения только по точным заранее заданным маршрутам; не авторизует и не исполняет операции.
- **Детерминированность:** Planner фиксирует capability snapshots при создании; изменение Registry после создания не меняет его поведение. Порядок доменов значим. Строки сравниваются буквально, без нормализации.
- **Проверки Planner:** добавлены пять регрессионных тестов в `dashboard/src/architect/SpatialPlanner.test.js`. Их реальный запуск не подтверждён; сборка также не запускалась. Ранее упоминавшиеся 55/55 тестов не следует трактовать как результат проверки Planner или как подтверждение текущего общего состояния без свежего прогона.
- **Границы безопасности:** наличие валидаторов и Planner не означает подключённую KVP policy/authorization gate. Capability adapters, provenance и Spatial Engine materialization не подтверждены как интегрированные.
- **Следующий шаг:** выполнить `npm run test:architect` из `dashboard/`, разобрать фактический результат, затем проверить `npm run build`. После этого отдельно оценить интеграцию с KVP authorization.
